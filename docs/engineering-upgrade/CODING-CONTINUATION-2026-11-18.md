# 长订阅会话 503 修复

## 根因与边界

2026-11-18 管理员统一编程会话出现 `standby conversation provenance cannot be verified`。
生产错误记录包含组 17、`gpt-6.2-sol` 的 57 次 503，均未选择上游账号。
备用付费策略全部关闭、付费尝试为零；订阅账号仍可调度。

备用身份保护会对请求的历史推理密文生成去重摘要，即使备用关闭也检查过去是否产生过付费状态，
以防禁用备用后把旧密文发往另一个身份。摘要收集在第 101 个不同值停止，而数据库层原先
无条件拒绝超过 100 个值。因此正常的长订阅历史被当成无法核验的付费历史，在调用上游前返回 503。

同一管理员已有 Key 的线上合成探针（101 段不同占位密文，不含用户历史或工具调用）在旧版本
0.109 秒复现该 503。占位密文本身无效；它用于比较校验层行为，不能当作完整会话成功证据。

修复只改变超过 100 个摘要的分支：同一用户、Key、分组和模型从未产生过已结算的备用密文回执时，
继续原订阅路由；存在此类回执时继续拒绝未完整核验的长历史，数据库查询失败也不放行。
原来的短历史匹配、身份隔离、账号凭证变更检查均保留。
付费备用长历史仍有原来的核验限制，不能据本次修复宣称其已支持无限续聊。

该问题与 API 实验的未知费用准入保护不同。后者只限制同一用户跨 Key 的未定价 GlobalAI
实验请求，不改变 Codex/Grok 配置并发。本次不调整任何并发、费用、周期或权限配置。
`API_KEY_REQUIRED` 则是请求缺少可识别 Key 时的 401，需要与本次 503 分别判断。
