# Grok 上游错误诊断升级

用户批准为下一次 Grok 故障补齐证据，并沿用本项目提交、推送 fork 和线上发布流程。本轮仅增强诊断，不改变冷却时长、故障转移、账号调度、个人额度或计费规则。

## 故障依据

北京时间 11 月 9 日 23:36:13，Grok 编程母账号 14 收到上游 HTTP 403，进入现有 30 分钟冷却。管理员于 23:53:25 恢复状态后，成功完成三次请求；23:53:58 又收到 403，再次进入冷却。错误记录 1038、1070 仅保存通用错误和 xAI 请求 ID，没有可解释的上游错误明细。

这证明了临时不可调度的触发路径，但不能证明封号、订阅失效、额度耗尽或风控中的哪一种根因。原始诊断证据位于本地忽略目录 `output/grok-scheduling-20261109/`，本轮不回填或伪造历史原因。

## 诊断内容与边界

复用 `ops_error_logs.upstream_errors`、`upstream_error_detail` 和现有管理员错误详情，不新增数据库迁移、接口或前端资源。每条上游尝试独立留痕，晚到的认证失败仍按原语义单独归属，前面的 HTTP 错误保留在尝试列表。

- 保存上游请求 ID、去除认证信息及查询参数的上游地址、模型与入站端点。
- 仅投影错误码、错误类型、错误文本摘要，丢弃 JSON 中的输入、输出和其他非错误字段；错误码／类型不能借助对象或数组夹带额外内容。
- 白名单记录 Retry-After、WWW-Authenticate、请求 ID、CF-Ray、限流及部分订阅／权益响应头；Authorization、Set-Cookie、Cookie 不进入采集。
- 记录本次凭据获取是否成功、来源、刷新／等待结果和所持账号快照的到期时间，不保存凭据值。不额外刷新令牌或查询上游；到期时间需结合刷新／等待结果解读，不能将旧快照当作后来由其他 worker 刷新出的令牌的最终到期时间。
- 未知 403 保持 `reason=unknown`；明确的订阅／权益、内容策略等信号才归入对应诊断类别。该类别不参与调度决策。
- 空正文、HTML、无效 JSON、超过 32 KiB 的错误体明确标记；HTML、无效 JSON 和超长原文不保存。文本错误只保存限长脱敏摘要。
- 先脱敏再截断，防止截断保留长密钥前缀。单条诊断编码后最大 8 KiB，超出时舍弃响应头并收缩摘要，继续使用现有队列的数量／字节上限。
- 认证状态使用非凭据字段名；白名单响应头使用名称／值列表，避免既有通用脱敏器把 token 用量头及整个认证状态误删。未放宽全局脱敏规则。
- 客户端错误响应及学员 DTO 继续沿用原权限边界；诊断数据通过管理员现有错误详情查看。

HTTP Responses、Chat Completions 及桥接、图片／视频／HTTP 语音的错误记录接入同一采集器；流内终止失败保留安全的错误投影，不需要打开原始错误体日志开关。纯实时 WebSocket 握手中未由底层接口暴露的正文，不声称能够采集；本轮不改变底层握手接口。

下一次真实失败后，在 **管理员 → 运维监控 → 请求错误 → 详情** 查看“上游诊断／上游尝试”。如果上游仍不给出说明，会显示未知及可用请求 ID，需由上游侧继续追查；本轮不会人为制造 403、清除账号状态或发送真实付费调用来验收。
