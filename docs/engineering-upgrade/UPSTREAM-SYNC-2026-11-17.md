## 冲突与定制适配

1. `api_key_auth_cache_impl.go`：两边都使用版本 28、字段含义不同，合并后提高到 29，
   同时保留 MILE 钱包／隐私字段及上游 `force_openai_ultrafast`，使旧快照失效。
2. `gateway_usage_billing.go`：保留发送结果进入数据库前的 reservation 持久交接，
   并保留上游在结算后为缓存同步另建超时上下文的行为。
3. 上游按用户合并的批量计费只实现标准余额／订阅／Key／账号副作用，不能替代 MILE
   编程账本、实验钱包、在途计费及恢复。带这些字段的命令继续通过原单条结算；
   原始 `ApplyBatch` 也在认领去重键之前拒绝这些命令，防止遗漏业务副作用。
   普通计费继续使用上游批量优化，不修改历史指纹、原扣点、个人周期或恢复协议。
4. Ent 自动合并没有文本冲突，却使 15 个 Group 运行时字段引用错位；第一次真实 Go
   测试因此在初始化阶段报 bool/string 类型转换 panic，原失败证据保留。
   按实际变更的合并 schema 执行一次 `go generate ./ent`，纠正 runtime 与 mutation 两文件；
   重新核对 67 个字段中的 51 个生成引用，索引错误为零，随后重跑相关实际测试。

478 个 fork 定制应用路径中，64 个与上游修改有交集；其余 **414 个路径的内容保持**。
指南导航、共享 Base URL、MILE 入口、原 Provider／Key 语义、个人重置、持久预留／计费及
shadow 规则保留。新增浏览器工具 `review_admin_groups.py/.cjs` 复用现有 Playwright CLI
与 mock 框架，后续可直接验证默认档位、显式保存、重开、取消及三个视口尺寸。
