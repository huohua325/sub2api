## 客户端兼容

新增统一编程模板使用 `model_provider="milelab"` 和 `[model_providers.milelab]`，`requires_openai_auth=false`，MILE Key 显式配置为 `experimental_bearer_token`。用户可以保留有效的旧 `auth.json`；选择 milelab 时使用该配置中的 MILE Key，无需删除旧登录信息，也不为迁移生成或覆盖 auth.json。已有 config.toml 只合并相关项，不整文件替换，不改写历史会话的 Provider ID。

当前仅更新获授权统一编程入口的模板；首页、开始使用、普通 OpenAI / Grok / Composite 实验模板保留原语义。未加入测试的用户无需修改客户端。原有配置继续使用原 Key、分组和额度；只改 Provider 名称不会自动获得 Grok 权限。已用上一轮本地 `sub2api` 模板的测试者也可沿用其 Provider ID，只需保持对应配置一致，避免历史会话匹配变化。

## 开放规则

复用现有 `groups.is_exclusive` 和用户 `allowed_groups`，无新数据库迁移、无独立特性开关表：

1. **管理员验证**：新建、复制统一编程分组均默认专属；不支持直接转换现有分组，避免原 Key 和授权名单继承新用途。管理员可访问该编程分组；其他专属分组权限规则不变。订阅型分组仍需满足其现有订阅条件，推荐本场景使用标准分组绑定 OAuth 上游账号。
2. **指定用户测试**：保持专属，在“用户管理”中将此分组授权给选中的测试用户。用户看到“统一编程”后可创建专门测试 Key；不会搬动其旧 Key。撤销名单权限后，已有 Key 的后续请求也被拒绝，已持久化的计费任务仍正常结算。
3. **全面开放**：验证完成后，管理员后续编辑时明确将该分组设为公开。受限公开分组用户仍遵守原权限规则；开放不会自动更改任何旧 Key 或补额度。升级本身不会执行这一步。

后端同时检查可见目录、Key 创建／变更和网关权限。前端在没有获授权统一分组时不显示新用途，猜测 `?purpose=coding` 不会打开隐藏功能。API 调用不能绕过权限。复制的分组继续保持停用，并重新开始专属预览；已公开源分组不受影响。

本规则已写入 AGENTS.md，作为以后新增功能的默认交付流程；本轮不将现有成熟功能重新设为预览，也不建设无实际用途的通用开关后台。
