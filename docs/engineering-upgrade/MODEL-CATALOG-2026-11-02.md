## 学员模型页的数据契约

`GET /api/v1/user/models` 使用现有 JWT、用户模式守卫和面板限流。通过与创建 Key
相同的 `GetAvailableGroups` 权限入口获取分组，再汇总各组关联的持久启用账号；
不把管理员全部账号公开给学员，也不因暂时限流、额度耗尽而把型号从目录隐藏。
停用账号、关闭调度的账号、不可访问分组和不符合分组平台条件的账号均不参与。

- OpenAI 复用网关的账号鉴权目录来源；其他平台使用已有上游模型列表能力。
- 应用账号模型映射、别名、分组白名单、退役模型及既有路由限制。复制的是客户端应填写的公开模型 ID。
- 同平台同 ID 合并，附带可用分组；同 ID 不同平台保留各自记录。
- 分组权限每次重查，不缓存学员目录。HTTP 响应为 `private, no-store`。
- 只返回模型 ID、显示名称、平台、可用分组、目录来源和观察时间；不返回账号 ID、Key、上游地址、提示词或上游错误详情。

账号发现结果短期缓存一分钟，五分钟内的过期结果可以作为最近缓存返回并后台刷新；
失败退避三十秒。缓存按账号、凭据和代理区分，最多 512 个条目，合并并发发现；
页面汇总使用四个工作协程，发现调用另设共享四槽限制及六秒超时，整批发现最多等待八秒。
OpenAI 自身的共享目录缓存继续保留其原有刷新机制。只读目录请求不产生模型对话或额度消耗。

上游失败时，仅以管理员显式配置的有限模型名回退，标记为“配置模型，待确认”；
不拿后端内置型号表冒充实时目录，不把通配符当作可复制的模型名。缓存结果也明确标记。
上游返回权威空目录时保留空结果，不自动补默认型号。没有模型列表接口的供应商仍受此限制。

前端删除旧 `experimentModels.ts`，保留搜索、家族筛选、复制反馈和接入指引。
未知型号归入“其他”，不会被写死的家族列表丢弃。首批渲染 60 条，后续按需展开，
搜索仍覆盖完整目录。页面进入或点击刷新时读取目录，不增加全站轮询。

旧页的静态元/百万 token 价格不再跟随动态模型显示，避免将旧价格或零值误标到新模型。
本次没有改计费价格、个人额度、周期、官方扩容或重置规则。
