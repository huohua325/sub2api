# MILE Lab 上游合并流程

先读根目录 `AGENTS.md`、[额度重置规范](CODEX-GLOBAL-RESET-RUNBOOK.md) 和 [最近合并基线](upstream-sync.json)。每次同步另写一份 `UPSTREAM-SYNC-YYYY-MM-DD.md`，不要覆盖旧记录。

## 确定范围与保留历史

1. 检查工作区未提交内容；在独立 worktree 操作，保留用户文件。
2. `git fetch origin --tags`、`git fetch fork`；记录合并前 fork SHA、上次已纳入的上游 SHA、此次目标 SHA，以及目标是否包含正式版之后的提交。分支名和版本号不能替代提交关系。
3. 用 `git merge-base --is-ancestor <上次上游 SHA> HEAD` 确认历史，再查看 `git log HEAD..<目标 SHA>` 和 `git diff HEAD...<目标 SHA>`。
4. 使用固定 SHA 执行 `git merge --no-ff --no-commit <目标 SHA>`，审查后形成真正的双亲 merge commit。**上游同步不能 squash 或覆盖源码目录**，否则下次无法从 Git 历史可靠判断已经纳入哪些上游提交。禁止向 `origin` 推送，只向自己的 `fork` 推送。
5. 文本无冲突不等于业务无冲突。检查自动合并、公共请求入口、计费结果、权限、缓存字段和代码生成产物。只有 schema 实际改变时才按需要重新生成 Ent；不要无故重生成。

## 必须保留的定制

| 范围 | 检查重点 |
| --- | --- |
| 学员体验 | MILE 标志、浅色光谱主题、导航和功能过滤、Key 列表空间、模型筛选、接入指引、Grok 单文件 config.toml、复制及密钥遮罩 |
| 学员额度 | Codex 50 / Grok 30 默认值、个人独立七天、实验钱包月周期、百分比与倒计时、学员不显示具体点数 |
| 重置及历史 | 原注册/钱包起点、稳定全体重置事件 ID 与真实时间、原请求账本、纠正及对账记录；候选确认不依赖手动表单且不截断事件时间精度 |
| 并发及计费 | 同用户跨 Key 的协调、官方增量分摊、持久预留/交接/恢复、协议入口覆盖；升级不自动启用 enforce |
| 运维 | 现有部署目录、Caddy、MemSlides、已启用功能和私密配置 |

对没有计划修改的定制范围，比较合并前后的 Git blob，记录确实未改动的路径。对有交集的范围，记录逐项取舍及回归用例，不用整文件选择 ours/theirs 来掩盖冲突。

## 验证与失败基线

- 运行前端全量 Vitest、类型检查、只读 lint、国际化检查、生产构建。
- 运行后端相关单元/竞态测试、Go vet、相对合并前 fork SHA 的增量 lint；全量测试有失败时，在合并前 SHA 重现并逐项比较，不能记成全绿或跳过。
- 必须使用隔离 PostgreSQL 的 `SUB2API_QUOTA_TEST_DSN` 实际运行 `go test -race ./internal/repository -run TestCodingQuotaDB -count=1`。记录通过、失败、跳过数量；缺 DSN 的 skip 不算通过。
- 审查所有迁移文件的内容和文件名。既有迁移校验和必须保持；新增迁移单独验证。不能把真实生产重置事件写进通用迁移。
- 在实际生产构建上检查学员与管理员的受影响流程。浏览器 mock 应明确拦截 API，不能为验证功能向生产确认重置或发起付费模型请求。
- 最终独立审查合并后的代码；记录覆盖边界及任何尚未完成的验证。

## 提交与发布

检查通过后提交 merge commit，再提交最终验证/发布记录；将上游固定 SHA、合并前 fork SHA、验证文档写入 `upstream-sync.json`。用 `git merge-base --is-ancestor <此次上游 SHA> HEAD` 验证纳入关系。

发布授权已包含在线升级时，先备份数据库、程序和配置并验证备份目录，再替换 MILE 自己构建的程序；不要直接换成官方镜像而丢失定制。按同一参考时刻核对所有已确认事件、个人周期、钱包起点、原账本、纠正/对账及持久计费任务。允许正常结算推进，但不能删账、重复扣点或因升级恢复已耗尽额度。保留 shadow 模式及观察起点，不能自动启用 enforce。

发布后核对公开资源哈希、应用与 MemSlides 健康、启动错误和迁移结果。回退只回退程序/模式并继续处理已持久化任务，不能恢复旧数据库覆盖新消耗。发布记录写明运行时源码 SHA、程序哈希、备份路径、检查结果；文档提交的 SHA 可以晚于运行时源码 SHA。
