# 个人额度与重置周期实现记录

日期：2026-10-27。本次修改已在工作区实现，尚未应用到生产数据库。业务规则依据 [QUOTA-REDESIGN.md](QUOTA-REDESIGN.md)，旧行为见 [QUOTA-AUDIT.md](QUOTA-AUDIT.md)。

## 生效规则

| 用途 | 每人默认额度 | 周期与计量 |
| --- | --- | --- |
| Codex | 50 点 | 独立的 168 小时；主官方七日额度每消耗一个百分点计一点 |
| Grok | 30 点 | 独立的 168 小时；按官方周额度增量归集 |
| API 实验 | 500 元，可沿用管理员配置 | 北京时间自然月；GlobalAI 请求按匹配的官方消费日志计人民币 |

个人周起点沿用已有 `user_purpose_allowances.window_start`，没有旧起点时采用注册时间。长期不访问也按整数个 168 小时推进，不从下一次访问时间重新计时。实现不依赖数据库时区是否有夏令时。

Codex 全体异常重置确认后，以事件发生时间建立新的个人七日周期，仅影响 Codex。事件前开始、之后才完成的请求归原周期；确认接口用事件 ID 保证幂等。同一事件重复确认不会再次延长周期。

母账号自然换期、切换账号、下线或删除账号不清除个人已记账点数。同一人使用多个账号合并计数，同一账号的多个用户分别记账。

## 数据与调用链

迁移 [254_coding_quota_ledger.sql](../../backend/migrations/254_coding_quota_ledger.sql) 新增请求账本、官方观察、账号计量基线、异常重置事件与实验补账记录。请求记录和原有计费去重在同一事务提交，不依赖可清理、尽力写入的 `usage_logs`。

增量分配采用：`ΔP × 本请求标准成本 / 区间所有相关请求标准成本`。权重保存为发生时的 `TotalCost`，不采用个人优惠或分组倍率后的 `ActualCost`。区间尾差确定性分配到八位小数，总额守恒。已结算区间不被后来的请求重新分摊；暂估值被实际区间分配替换，不重复叠加。

认证、学员卡片和管理员个人额度均读取同一份个人账本。认证和学员页面不访问上游；查询限定用户和其当前周期，并使用索引。管理员列表批量读取。未新增个人汇总缓存或请求前的预占表。

后台每 10 秒运行一次，单轮最多 30 秒；用 PostgreSQL 事务锁串行结算同一账号，可重放。观察至少等待 30 秒，让异步计费队列有时间入库。Grok 沿用只读账单探测；Codex 过期快照通过只读 usage 接口刷新，包含闲置或耗尽账号。官方探测有十分钟间隔，不发送模型测试对话。Codex 仅取主 `rate_limit` 中的 604800 秒窗口，不混入五小时或 Spark 桶。响应头剩余秒数优先以 HTTP `Date` 为基准，避免长流式响应把重置时间向后推。

实验账单暂缺时持久化待核对状态，后台按一分钟起的指数退避重查，最大间隔 64 分钟。匹配成功后一次性补扣原月份个人金额，并修正已存在的零费用用量行、请求时配置的 Key/订阅/账号计数。已关闭的次级窗口不重新打开；过期月份不占新月份额度。缺少上游请求 ID 的记录保留为未解决状态，不能伪装成已确认免费。

## 特殊重置操作

入口：管理员 → 用量监控 → Codex 全体异常重置。输入发生时间与核实原因，二次确认后提交。时间输入按浏览器当地时区展示，发送的是绝对时间；仅允许确认最近七天内的事件。

- `GET /api/v1/admin/usage-monitor/codex-resets`：最近候选与已确认事件。
- `POST /api/v1/admin/usage-monitor/codex-resets`：管理员身份、事件 ID、发生时间、原因及显式 `confirm: true`。
- 当前单账号只会形成候选，由管理员核实后确认。
- 自动确认要求所有配置中的 Codex 编程母账号都有异常证据，至少两个不同上游身份，异常时间相差不超过十分钟，且有后续读数佐证。没有读数或离线的成员不会从判断分母移除。本地重置卡标记排除在全体重置证据之外。

## 页面与异常状态

额度是否耗尽比较真实点数；例如 `49.8/50` 即使显示为 `100%`，仍不标成耗尽。读账失败阻止继续调用，前端显示读取异常。待结算、无法完整归属与迁移估算分别提供状态。

页面根据请求往返中点估计与服务器的时差。倒计时过期显示“等待服务器确认”，触发一次刷新，不自行把旧用量改成零。刷新失败保留旧读数并显示异常；页面隐藏后暂停轮询，恢复时重新同步。

## 迁移与历史

通过项目现有迁移机制执行 254，再启动新版服务；本次只在隔离的本机 PostgreSQL 测试实例运行迁移，没有连接生产数据库。

迁移保留原个人周起点；能计算的旧 `U/S×P` 余额作为 `imported` 估算期初记录导入，不声称还原了逐请求历史。缺少可信历史基线的部分无法精确重建。已有可靠快照用于新计量起点；畸形时间和旧设置 JSON 不应阻断迁移。

设置 `official_point_budget` 先备份到 `quota_ledger_previous_point_budget`。保存值恰为 Grok `80` 时迁到 `30`；其他自定义值保留。旧数据没有标识“80 是默认还是人工设置”，因此人工明确设置为 80 的情况也会改到 30，部署时须检查备份。Codex/Grok 的旧元钱包开关不再选择旧算法。

回滚不能直接删除新账本或恢复旧的动态分摊算法；否则会丢失切换之后的已确认消耗。应保留备份、期初记录和新请求明细进行对账。

## 已知计量边界

1. 官方累计百分比不是逐对话扣点。区间内采用权重分配；读数精度、长请求跨观察、站外消费及缺少基线会影响归属。无法完整计量的请求保留 `pending/unmetered` 与已有估算；没有校准样本时估算可能为零，但状态不表示确认免费。当前尚无自动追溯所有不可归属消耗的能力。
2. 一个账号的 1% 定义为一点，不同套餐的算力未做等价换算。重复导入同一上游凭证也应在账号治理中避免；本次没有重构凭证池去重。
3. 采用请求前检查、完成后结算。尚未加入个人额度原子预占；并发或长流式请求可能超过软上限。不能承诺绝对不超额。
4. 异常检测依据账号观察推断，不能取代官方事件通知。成员变化、站外使用重置卡等情况仍需要管理员核实；误确认没有一键撤销入口。
5. 数据库锁防止重复结算，多实例上游探测尚未做分布式合并。用量日志沿用尽力写入，丢失或迟于补账写入的日志不保证全部回填；财务记录以持久化实验账本为准。
6. 本项目现有 `wire_gen.go` 包含手工接入的额度服务设置；重新生成 Wire 时要保留这些连接及 worker 启停，不能只替换生成文件而遗漏接线。
