# 并发额度控制与用量监控

状态：按平台所有者 2026-10-28 已批准方案实施；线上先 shadow，不能跳过每用途 24 小时、20 次完成请求的观察门槛。

## 业务约定

- Codex/Grok 个人额度、原注册／钱包七天起点、已确认全体异常重置、原账本、期初记录与历史追加纠正完整保留。API 实验、官方增量分摊和母账号调度不变。
- S 为已结算／期初加纠正，P 为已入账估算，R 为在途预留，E 为新增估算，L 为限额。S>=L 始终拦截；可靠且 S+P+R+E<=L 原子预留；否则同用户同用途最多一条进行中请求。既有请求不中止，允许有限暂时超额。
- 倍率使用所选母账号当前官方窗口累计有效点数／原始成本权重。默认至少 20 条已结算样本、正倍率、观察不超过 20 分钟；无可靠样本不等于免费。原始模型成本不乘用户售价倍率。
- PostgreSQL 为预留权威；锁顺序母账号→个人（多对象排序），幂等标识由服务器生成，内部重试复用，保留原计费幂等指纹。
- HTTP 一次逻辑请求一个预留；WebSocket 每轮一个，首轮后续轮次均覆盖。只在发送上游前准入；已发送结果未知保留待核实证据。
- 完成后持久交接规范计费命令，原账本入账和关闭预留同事务；核心任务不可丢弃。每 30 秒续期，120 秒失联转待核实，不自动退款，不永久占执行槽；迟到结果可恢复。
- 请求按原开始时间归属个人周期；事后补记全体重置也按原时间筛选占用，不按部署、纠正或恢复时间补额度。
- 真耗尽 403 PURPOSE_QUOTA_EXHAUSTED；新增并发占满 429 CODING_QUOTA_BUSY、Retry-After:5；存储失败 503 CODING_QUOTA_UNAVAILABLE。
- 学员百分比仍为 S+P，不含 R；增加处理中、结算中、并发暂满、不可用提示，不显示点数。管理员现有用量监控增加分项、可信度、原因、待核实、任务重试和纠正证据；只读明细游标分页默认50最多100，不含完整Key／对话／请求体。
