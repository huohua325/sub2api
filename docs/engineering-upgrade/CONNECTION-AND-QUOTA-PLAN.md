# 学员接入与额度可信度设计

日期：2026-10-27。状态：待实施设计。基于已上线的 `0.2.18-mile.20261027.ui2`，本文件不代表功能已经上线。

## 1. 本轮交付与约束

本轮交付两项：学员从创建 Key 到完成配置的连续流程，以及个人额度状态和周期的验证。延续浅色光谱、MI 品牌、Sora 数字和现有控件；密钥列表维持紧凑布局，接入内容在操作后展开。

- Codex、Grok 学员界面仅展示百分比、状态和重置时间，含提示、弹窗、无障碍文本和错误信息，均不展示具体点数。API 实验继续展示人民币金额。
- 额度按用户、用途聚合，不为每个 Key 再复制一份个人额度。同一用途的多个 Key 共同使用该用户对应额度。
- 保留现有分组、权限、功能开关及其他客户端接入方式。默认展示与用途相符的入口，其他受支持方式收进可展开区域。
- 保留本轮已改善的 Key 列表空间：不在列表上方增加常驻步骤条、大卡片或接入教程。
- 保留 Vue 3、Vite 5、Tailwind 3；先使用现有接口和字段。数据结构变更必须由实际核对结果支持。

## 3. 接入流程

```mermaid
flowchart LR
    A[工作台 / 模型 / 开始使用] --> B[选择用途与分组]
    B --> C[创建 Key]
    C --> D[该 Key 的接入面板]
    E[现有 Key：使用密钥] --> D
    D --> F[选择客户端与系统]
    F --> G[复制配置或下载单个配置文件]
    G --> H[在本机运行]
    H --> I[查看调用结果与用量]
```

### 创建 Key

继续使用现有创建表单。上部呈现三个用途，随后选择实际可用分组和名称；IP 限制、有效期、自定义 Key 等原有设置完整保留。管理员已有管理能力不收缩。

- 从某用途的入口进入时预选该用途，学员仍能更改；仅有一个可用分组时可自动选中，多个分组时清楚显示选择。
- 无可用分组的用途显示“当前未分配此用途的分组”，不自动切到其他用途后继续创建。
- 创建提交期间禁用重复操作。创建成功与列表刷新分别处理：刷新失败不能导致再次创建。
- 创建成功关闭表单，使用返回的新 Key 与提交时的分组快照打开接入面板。返回值缺少分组时，以已确认的 `group_id` 对齐当前可用分组；信息无法确认则显示待补全状态，不生成猜测配置。
- 更新既有 Key 后保留原有保存行为；不强制再次进入接入流程。

### 接入面板

桌面优先复用现有宽弹窗：内容宽度约 880–960px，上下保留视口边距，正文独立滚动。375px 使用接近全屏的弹层，标题、关闭与底部操作可达。键盘焦点进入、约束和返回沿用并验证公共弹窗机制。

```text
配置 Codex                      研究项目 Key         关闭

客户端 [Codex CLI ▼]        系统 [Windows | macOS / Linux]

服务地址     https://…/v1                      复制
API Key      sk-…                              显示 / 复制

配置文件路径
┌ config.toml ───────────────────────── 复制 / 下载 ┐
│ 与当前客户端、模型、地址匹配的配置                │
└─────────────────────────────────────────────────┘
┌ auth.json ─────────────────────────── 复制 / 下载 ┐
│ 默认隐藏真实密钥；复制使用实际内容                 │
└─────────────────────────────────────────────────┘

下一步：在本机启动客户端
常见问题〔展开〕                其他接入方式〔展开〕

返回 Key 列表                              查看使用记录
```

三个用途共用结构，内容随用途变化：

| 用途 | 默认内容 | 成功后的去向 |
| --- | --- | --- |
| Codex | 当前支持的 Codex 客户端配置；原有认证模式保留，兼容性经过测试后再调整默认值 | 本机启动方式、按此 Key 筛选的使用记录 |
| Grok Build | Grok 客户端配置、当前支持的启动命令 | 本机启动方式、按此 Key 筛选的使用记录 |
| API 实验 | 协议兼容的请求示例、服务地址和可用模型选择；按分组现有协议能力呈现 | 复制示例、查看该 Key 的调用记录 |

用途不等于协议：API 实验分组可能来自不同平台，不能统一假设支持某个请求端点。模型选择采用现有真实目录或已验证支持的模板；无目录时显示模板的适用范围，不捏造可用性。

### 复制、下载和状态反馈

- 代码可见内容与实际复制内容区分建模。密钥默认遮罩；复制或主动下载时才使用真实值。
- 每个文件独立显示“已复制”；失败时给出可手动选择的内容。切换客户端、系统、模型或 Key 后清理旧复制状态与异步结果。
- 下载直接在浏览器生成文件，不上传配置。文件名和路径提示由配置模板定义；不自动覆盖用户本机文件。
- 真实 Key 只放在当前操作所需的内存中；不写入路由参数、额外 localStorage、遥测或日志。关闭面板、切换 Key、退出账号时释放本轮会话数据。
- “已复制”“已下载”只说明操作完成，不能显示为“接入成功”。首轮不在打开面板时自动发送模型请求，也不把获取模型目录成功当成生成请求成功。
- 日后若增加实际连接测试，必须由学员明确点击，说明可能产生用量，并使用对应协议的标准计费路径；不建立隐形免费探测通道。

### 开始使用页

保留 `/guide`，调整为先选择用途、再看当前用途的准备/配置/排错步骤。已有 URL 锚点继续可用。

未选择 Key 时显示占位配置和“选择现有 Key / 创建 Key”；选定后在接入面板内展示真实配置。教程正文不常驻真实 Key。模型页可以携带用途、模型标识进入接入流程，但所有值都要按当前权限和实际分组重新验证。

## 4. 额度卡片与数据状态

继续在工作台显示三类额度，新增或明确“已用”标识，避免大百分比被理解为剩余百分比。卡片保持现有高度范围，详细解释放在可展开区域。

```text
Codex                         用量待同步
已用 9%                     〔不显示点数〕
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
预计 23小时1分后更新
本周期：10月21日 16:00 — 10月28日 16:00
部分调用的用量正在同步，百分比可能调整。    额度说明
```

“额度说明”包含：个人周期起止、北京时间的绝对重置时间、当前数据状态、最近核对时间，以及确认的平台异常重置说明。未知时间显示“暂未取得更新时间”，不能填成当前时间。

### 状态按两个维度处理

余额能否继续使用由后端 `blocked` 和对应原因决定；数据是否完整由 `data_status` 决定。界面文案不能把其中一个替代另一个。

| 状态或条件 | 学员展示 | 保留的数值与操作 |
| --- | --- | --- |
| `current` 且未耗尽 | 数据已同步；有剩余额度 | 百分比、重置时间 |
| `estimated` | 含历史估算 | 保留估算读数，解释后续周期按正常账本计算 |
| `pending` | 用量待同步 | 保留当前读数，说明近期调用尚在核对 |
| `partial` | 部分用量待核对 | 不把未核对部分显示为免费，也不暴露点数 |
| 已确认耗尽 | 本周期额度已用尽 | 保留已用比例和重置时间，提供查看使用记录 |
| 首次请求失败、未知读数或 `error` | 暂时无法读取额度 | 显示“—”，保留重试；不显示 0% |
| 刷新失败但有旧数据 | 显示上次读取结果 | 标记未更新，保留已知限制和重试 |
| 倒计时到期、服务端尚未返回新周期 | 正在确认新周期 | 不自行清零；保留旧周期结果并重新读取 |
| 已确认 Codex 平台异常重置 | 本周期已按平台更新 | 使用服务端新周期，说明只影响 Codex |

耗尽和待核对可以同时出现，不丢失任一信息。只显示为四舍五入后的 100% 不足以判断耗尽。

不再用个人额度读数单独承诺“可调用”：上游维护、限流或渠道不可用需要由实际渠道数据或请求结果说明。额度核对失败是否阻止请求沿用后端规则，前端不能自行放开。

### 时间与刷新

- 使用服务器绝对时间与请求往返中点校时；倒计时为预计时间，展开后提供精确时间。
- 个人周为固定 168 小时；API 实验为北京时间自然月。默认规则与管理员已有覆盖均由服务端决定。
- 倒计时归零时合并刷新：同一个平台异常重置或共享截止点只发起一次有效刷新；失败允许手动重试，不制造高频循环。
- 保留现有每分钟轮询、后台标签暂停、恢复标签刷新。合并同时发生的手动/轮询/到期刷新，卸载后不落入失效组件。
- `server_now` 只表示服务端当前时间，不能作为上游账单或个人账本最后更新时间。必须先核实 `updated_at` 的实际语义；需要时用可选字段区分“页面读取”“账本结算”“上游观测”时间。
- 首轮不为每个额度卡再增加独立请求，不提前加载历史统计或图表。

## 5. 额度核对方案

先以只读方式核对当前生产状态，再在隔离数据库和 mock 上游中执行可重放测试。生产上不人为触发全体重置、切换账号或生成收费调用来制造样本。

### 核对口径

个人用量以个人账本为准。官方累计百分比的增量可以按区间请求权重分配，不能据此宣称精确测得每段对话的消耗。已确认区间不随之后新请求重新分摊；待核对估算被正式结果替换，不能重复叠加。

| 验证项 | 预期 |
| --- | --- |
| 同一用户使用多个 Key、多个母账号 | 同用途合并到同一人的本周期，不重复扣减 |
| 同一母账号服务多个用户 | 各用户仅有自己的消费；已归属增量守恒，不把未归属站外消耗强行分摊 |
| 母账号自然换期、切换、下线、删除 | 不清除用户已记账用量，不覆盖个人周起点 |
| 个人周边界、长时间未登录、跨界长请求 | 固定 168 小时推进，以既定请求归属时间划分，不从下次访问重新计时 |
| Codex 非自然重置 | 单账号候选需管理员确认；缺失全池证据不能自动确认；同一事件 ID 幂等，只更新 Codex |
| 异常重置前开始、之后完成的请求 | 按既定开始时间归属，不能转移到新周期并再扣一次 |
| 同一个结算任务重试、多个 worker | 不重复扣减，账本结果一致 |
| 观测下降、过期或乱序、上游暂不可达 | 保留待核对或异常状态，不自动视为零用量或全体重置 |
| API 实验延迟出账、跨北京时间月界 | 补记原请求所属月份，不能消耗新的月份；保留已有待核对状态 |
| 小数百分比被显示为 100%、未知读数 | 根据真实阻止状态判断；未知不转为零 |
| 客户端时钟快/慢、后台恢复、截止点刷新失败 | 不提前重置、不重复请求、不伪造新周期 |

现有 admission 前检查与完成后结算仍可能在并发下超过软上限。本轮单独记录实测边界；如果需要严格硬上限，再设计预占和释放，不在界面上承诺已解决。

### 交付证据

生成去标识的核对记录，包含窗口起止、请求数量、已结算/待核对数量、增量分配差额、异常重置事件及时间误差。管理员可看原始计量，学员仅看状态与比例。检查期间不复制或记录上游凭证、真实 Key 和对话内容。

每个结论区分“隔离回放通过”“生产只读核对”“真实端到端调用验证”，不把 mock 页面检查描述成真实客户端已接入。

## 6. 工程拆分与实施顺序

| 阶段 | 实施内容 | 完成标准 |
| --- | --- | --- |
| A：统一配置 | 提取 `connectionProfiles.ts`、`connectionConfig.ts` 等纯函数模块；集中用途识别、协议地址、客户端配置和兼容开关 | 同输入在弹窗与指引生成一致配置；路径前缀、已有 `/v1`、特殊字符与多平台协议测试通过 |
| B：贯通接入 | 保留并升级 `UseKeyModal` 为共同入口；创建后转接、独立接入会话、按用途默认客户端、复制与下载反馈 | 三条用途都能从创建进入配置；关闭/换 Key 无串值；编辑保存不被强制带走；Key 列表首屏空间不回退 |
| C：额度可信度 | 先核对线上字段和账本，再完善额度状态、周期说明与刷新合并；对发现的计算差异做最小修正 | 上述核对矩阵通过；用户端所有渠道不显示 Codex/Grok 点数，API 实验金额正确 |
| D：联合验收与发布 | 浏览器、实际配置文件、隔离客户端验证、生产只读核对和分阶段部署 | 提交截图、用例与核对记录，备份后发布，公网资源校验一致 |

配置生成器负责纯数据，面板负责交互和复制，Key 页负责创建与选择。接入会话使用独立状态，不与当前编辑/删除共用的 `selectedKey` 相互覆盖。异步模型目录继续按需获取，并在换 Key、关闭时取消和防止旧结果落入新会话。

新增 props 保持可选，现有调用方式和其他平台配置可继续使用。根据字段核对结果决定后端是否需要小范围调整；本轮不预设新表、新诊断 API 或完整缓存重构。

## 7. 验收清单

- 视觉：375、768、1024、1440px 与 200% 缩放；长分组名、长服务地址、代码长行、弹层滚动。维持 MI 风格，操作区用清晰白色表面，创建成功反馈使用短暂光谱强调。
- 可访问性：键盘完成创建、配置、复制与返回；标签明确、焦点不丢失；无障碍文本没有泄露点数和真实密钥；触控目标不小于 44px。
- 接入：无分组、单分组、多分组；创建成功但刷新失败；弹窗重开、切换用途/系统/Key；API 实验协议差异；已有客户端和认证方式兼容。
- 配置：解析生成的 JSON/TOML，核对 URL 与真实 Key 的正确转义；占位示例与真实配置一致；不能仅以字符串快照证明配置可用。
- 额度：执行第 5 节矩阵；确认后台标签暂停轮询、恢复校时、截止点不自动清零，异常状态不显示“可调用”。
- 性能：初始 Key 列表不加载接入面板的大型依赖或模型目录；面板按需加载；额度卡仍共用现有请求，不增加首屏历史统计。
- 检查：相关组件/请求/结算测试、类型检查、只读 lint、国际化完整性、生产构建；浏览器覆盖 Chromium、Firefox、WebKit，注明各自实际验证范围。

首个可发布结果为 A+B：配置统一、创建后直接接入、现有 Key 可随时重新打开。C 的只读核对与隔离验证可同时准备；根据证据完成状态与必要修正，再一并验收。
