# 开发到发布效率：第二阶段

根据个人额度重置发布的 75 分钟记录，落实已确认的优化：减少无关／重复检查，提前发现发布条件问题，在审查稳定后执行完整检查，并复用同一程序及差量。没有删减应用升级的真实额度竞态、数据保留或完整前端验收。

## 已实现

1. `delivery.py plan --base <固定SHA>` 输出应用／工具／文档变更范围、相关 Go 包、迁移隔离验证和广覆盖建议。工具／文档变更不自动发布应用；公共计费、鉴权及显式上游升级扩大覆盖，CI 原有广覆盖保持。
2. `delivery.py preflight` 无需程序包即可通过 SSH 运行只读预检：核对现网程序 SHA、备份空间、应用／MemSlides、shadow、Compose 实际计划和冻结 canonical hash。工具及敏感冻结配置仅进入服务器私有临时目录并自动清理，不停止服务、不创建数据库备份、不写业务数据。失败时不会留下旧的成功报告。最终部署仍即时复核。
3. `delivery.py freeze --reviewed` 在用例／路径验证及审查结束后冻结应用源码。`validate` 缺少冻结或源码变化会在安装／耗时检查前拒绝，完成后再次核对；dist、Vite 生成配置和文档／独立工具更新不算应用源码变化。冻结声明不替代实际测试及审查。
4. `delivery.py go-check` 原样保存 UTF-8 JSON 日志、通过／跳过／失败数量、失败根、包级失败和命令退出码。即使命令错误地返回零，JSON 中的失败也不能标绿；无实际通过测试或无 JSON 证据同样失败。基线失败继续如实记录，不提供忽略失败的开关。新增 `--go-executable` 避免 PowerShell JSON 引号返工。
5. 程序及版本未变、只有记录提交时保留已有程序源码 SHA，使后端构建命令身份稳定。差量按旧／新程序 SHA 缓存，每次重打包仍核对哈希并真实重建目标；损坏缓存重算。发布脚本修复不再要求重新计算同一差量；完整上传仍需明确 full-upload。

更新 AGENTS.md 及 tools/DELIVERY.md，明确开发阶段跑相关检查、审查后冻结、最终完整验证一次、只变工具不重复验证应用。新增差量测试所需的 bsdiff4 已加入现有 delivery-tools CI 的依赖安装步骤，未缩减应用 CI。

## 使用边界与后续校准

路径清单是建议，不是自动依赖分析或免检凭据；公共代码和未知依赖仍须审查扩大范围。早期预检不能代替切换前预检，源码冻结不能代替审查，差量缓存不能代替目标程序校验。应用升级仍执行既有完整前端、真实额度竞态和持久数据核对。

本轮只升级交付工具、约定和 CI 工具测试依赖；线上应用继续 `0.2.20-mile.20261113.quota1`，无需为了交付工具变更重启应用。证据见 `output/delivery-efficiency-phase2/`。计时从北京时间 2026-11-13 10:21:40 开始，最终耗时写入该目录 timing.json；下一次实际功能发布再验证 30–45 分钟目标，不能用工具自身检查耗时替代功能交付效果。
