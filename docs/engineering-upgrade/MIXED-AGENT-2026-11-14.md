## 配置依据

依照 [Codex 官方多智能体文档](https://developers.openai.com/codex/multi-agent)，自定义角色可设置 model 和推理强度，继承父会话的 Provider、权限和 MCP。主会话与子会话共用 milelab Provider 和现有统一 Key；配置 `[agents]` 并为 explorer / worker 设置 Grok 4.7。角色的只读或文件归属说明属于行为约定，不产生独立权限边界。

目录：`D:/codex_user/test/.mile-test/20261114-multiagent-taskfiles/`。

主智能体先把各自的完整任务写到 `.milelab/tasks/explorer.md` 和 `.milelab/tasks/worker.md`，角色开发者说明要求先读取固定任务单。这样无需理解加密消息正文；结果仍通过原生子智能体机制回传。每种角色只运行一个，避免固定任务单被并发覆盖。

- 主智能体：gpt-6.1-sol。
- explorer：grok-4.7，检查 URL 规范化实现，报告重复 `/v1` 与空输入校验问题。

本轮证明的是该小任务、固定两个角色、文件交接模式的可用性。没有验证单纯加一条子模型配置即可适用所有跨模型任务，也没有证明多智能体比单模型更快或更省 Token；长时间运行、同角色多并发和 VS Code 扩展仍需单独验证。Grok 最终点数结算也不由这项任务闭环验证代替。
