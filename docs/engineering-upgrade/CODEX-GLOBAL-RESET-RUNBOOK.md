# Codex 全体异常重置处理

## 确认的业务规则

正常情况下，Codex 个人额度以已有注册／钱包起点计算，每 168 小时更新一次。不是从首次使用起算，也不跟随某个母账号的自然换周或本地重置卡。

**OpenAI 官方全体账号异常重置是例外：所有已存在用户的 Codex 周期从事件实际发生时重新起算 168 小时。** 事件之前开始的请求仍归旧周期；事件之后的消耗继续保留。新注册或显式调整起点晚于事件的用户使用其较晚起点。Grok 和 API 实验不受该事件影响。

这不是在发现问题时把所有人的额度清零，也不是把倒计时改成“现在 + 7 天”。补记昨天的事件时，必须保留昨天事件之后至今的全部消耗，已经用完新周期额度的人仍然不能调用。

## 版本升级不重新设置

规则是项目长期业务约定，已确认的事件是 PostgreSQL 持久业务数据。应用启动只读取已有事件，版本号、镜像、可执行文件和缓存的变化都不是新的重置事件。普通版本升级不需要再次手工设置 2026-10-26 的事件，也不得用发布日期替换事件发生时间。

升级应保留 `coding_quota_reset_events`、`coding_quota_requests` 和 `user_purpose_allowances.window_start`。部署前后记录已确认事件的 ID、`effective_at`、状态和个人周期，确认没有丢失或改写；同一周期内，已耗尽状态必须保持。核对时固定同一参考时刻，避免把恰好跨过真实周期边界误认为升级引发重置。

历史重复扣点通过独立的 `coding_quota_reconciliations`／`coding_quota_corrections` 追加纠正，原始请求不改写。升级、备份和恢复必须一并保留这两表；个人有效用量和累计校准样本均计入纠正差额。纠正归属原请求时间，不是一次全体重置，不能延长周期或重复退款。详见[历史对账流程](QUOTA-HISTORY-RECONCILIATION.md)。

数据库备份包含这些数据。恢复较旧备份、迁移新环境或重建数据库时，需要同时保留备份之后产生的事件及消耗；不能只恢复程序或配置后重新初始化额度。历史修复脚本只用于一次性补记，不能加入普通部署或每次启动流程。

仓库根目录 [AGENTS.md](../../AGENTS.md) 要求后续额度开发、上游合并与发布遵守上述约定。只有平台所有者明确修改业务规则，才调整这一行为。

## 以后如何处理

1. **收集证据**：记录发生时间、原窗口结束、新窗口结束、百分比下降、账号范围与数据来源。排除自然换周、本地用卡、时区转换及响应头秒级抖动。账号切换、删除、离线不能成为给个人补额度的依据。

   同一官方窗口内，多个并行 Key 的响应可能出现百分比回退。结束时间仍在五分钟容差内时，保留计量最高读数，不把下降及随后的恢复当作重置或新增消耗。此类读数本身不构成全体事件证据；确有平台全体事件但观察不足时，继续走管理员确认流程。详见[并行 Key 计量说明](CONCURRENT-QUOTA-METERING.md)。
2. **确认范围**：自动确认要求所有配置的 Codex 编程母账号均有异常证据，至少两个独立上游身份、发生时间相近且有后续读数佐证。单账号或证据不足只产生候选，需要管理员或平台所有者确认全体性质。
3. **记录事件**：管理员 → 用量监控 → Codex 全体异常重置，填写真实发生时间和核实原因。接口为 `POST /api/v1/admin/usage-monitor/codex-resets`，须管理员登录、显式确认及稳定事件 ID；从 `GET` 同路径查看记录。发生时间在七天内可由现有界面补记；更早的事件应先做专项对账。
4. **补记不重扣**：事件写入 `coding_quota_reset_events`；查询按 `max(原个人起点, 已确认的最近事件)` 建立周序列。保留 `coding_quota_requests` 的每条原始记录与时间，不清除或复制消耗，不修改旧迁移文件，不改注册日期，也不直接改旧元钱包来伪装点数重置。
5. **验证一致性**：检查学员卡与鉴权都读取同一账本，所有受影响用户的 `period_start`、`resets_at`、`reset_reason=platform_reset` 正确；事件后耗尽用户必须保持拦截。确认 Grok、API 实验与费用记录不变。
6. **幂等与追溯**：同一事件使用同一 ID 重试，不另建“现在”的事件来解决倒计时。保存原因、证据、确认人及备份索引。历史运维修复使用独立来源 `operator_confirmed_history`，不伪装成某个管理员账号的操作。

首次启用或迁移计量账本时，额外核对最近七天是否已有官方全体异常重置；新的观察基线不能证明此前没有发生过事件。已有确认应随账本保留，历史漏记必须用实际发生时间补录。
