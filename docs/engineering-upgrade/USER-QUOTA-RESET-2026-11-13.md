# 管理员个人周期额度重置

用户确认：管理员选择普通用户及 Codex / Grok / API 实验，恢复当前周期可用额度，保留原周期结束时间；保留历史消耗，记录管理员、原因和重置记录。

实现约束：
- 独立的追加审计事件，不修改全体重置事件、钱包起点或原请求。
- Codex/Grok 按精确请求关联免计个人额度；母账号实际计量与校准不受影响。重置时已入账请求（包括待计量请求）归该事件，尚未入账的进行中请求正常结算。
- API 实验保留原始累计用量，通过当前窗口的审计基线扣除已重置部分。
- 必填原因、二次确认、稳定 UUID 幂等键、原周期校验；只允许普通用户。跨周期或幂等键载荷不一致返回冲突。
- 在现有用户额度弹窗展示三种用途、周期结束时间、重置操作与最近记录。用户切换时丢弃旧响应。
- 验证：真实 PostgreSQL 竞态与账本保留测试、API 权限与输入测试、组件及浏览器完整操作；最终前端全量检查与单次构建。
- 上线不操作真实用户额度；保留 PostgreSQL、Redis、Caddy、MemSlides。使用新事件后禁止回退到不理解该事件的旧程序，禁止恢复旧数据库。

## 使用

管理员进入「用户管理」，选择普通用户的「更多 → 平台限额」。弹窗顶部「个人用途额度」分别提供 Codex / Grok Build 的本周重置和 API 实验的本月重置。选择用途、填写原因并确认，原周期结束时间保持不变；最近 20 条记录展示用途、管理员编号、原因和时间。重置不增加个人上限，不影响其他用户或用途。

普通管理员会话／全权管理密钥可使用。受限管理密钥须显式获得 `users.purpose_quotas.read` 和／或 `users.purpose_quotas.reset`，旧平台限额权限不会自动扩权。

GET /api/v1/admin/users/:id/purpose-quota-resets 返回用途周期和最近记录；POST 同路径接受稳定 UUID `id`、`purpose`、原 `period_end`、`note`、`confirm=true`。响应丢失须复用同一 UUID 和载荷；自然周期改变时重新读取并再次确认。客户端输入不能提供管理员编号或改变目标用户。

## 持久数据与回退

新增 `personal_quota_resets` 与 `personal_quota_reset_requests` 均为追加审计表。Coding 的关联键包含请求和重置事件，允许补录全体异常重置改变周期后再明确重置个人额度。历史记录、原扣点、校准、容量与纠正、持久任务均保留。API 实验计数器不清零，按同一窗口的已审计基线计算个人有效用量。

完整发布使用 tools/full_upgrade.py，原前端通道继续拒绝本次变更。首次上线之前不执行真实个人重置。若新功能已被使用，不可回退到忽略个人重置审计的旧程序；不能用旧数据库恢复覆盖新消耗。

## 审查与取舍

独立审查发现的三项 Important 均已写测试复现后修复：实际 API 错误的顶层 reason；补录全体重置后的跨事件请求关联；排队准入按当前时刻应用个人重置。

保留的次要项：弹窗关闭后的旧请求可能显示通用结果提示（不会重置其他用户）；用量监控旧字段 stored_used_amount 及修改实验上限的即时响应存在原始／有效口径显示差异，刷新后显示有效用量。数据库原始值保留。真实并发计费与新增审计表保留会在升级测试中单独核对。
