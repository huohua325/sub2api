## 管理与调用

管理员在同一个“API 备用”页面选择现有分组：

| 分组入口 | 支持的平台 | 固定点数归属 |
|---|---|---|
| Codex | openai | Codex 原周周期 |
| Grok Build | grok | Grok 原周周期 |
| 统一编程 | openai 或 grok | 按所选平台归属原周周期 |

只接受 `usage_kind=coding` 的上述分组。独立分组的平台自动固定，不能把 Grok 备用计入
Codex，或把 Codex 备用绑定到 Grok Build。实验分组、其他平台和停用分组不出现在新建选择器。
切换分组会清除账号选择和审核确认；已创建策略的分组、平台和型号仍不可修改。

两个客户端的现有模板均使用 HTTP Responses，因此不需要改 Key、Base URL、Provider、
`auth.json`、`config.toml` 或旧会话。现有供应商密文不能跨账号迁移等会话限制继续适用；
需要新会话时按原备用规则提示，不承诺无条件续接。Chat／Messages／WebSocket 不因此获得付费接管。

普通用户没有菜单、页面和管理接口权限，也不能实际使用付费备用。策略默认关闭，启用仍须
管理员明确核实同型号能力、官方 USD 价卡、折扣倍率、额度点数及预算；关闭后已发送任务
仍继续恢复和结算。只有完整主订阅池全部满足有时限的明确失效条件才允许接管，繁忙、普通
限流、网络故障和未知状态仍不触发付费。

## 备用角色与原有流量

独立分组原本可以包含普通 API 账号，本轮不把所有 API 账号一律改为备用。
策略里明确选为备用的账号才具有该分组的备用角色，角色从当前和不可改写的历史审批记录
读取，覆盖所有型号。关闭、过期、编辑策略、解绑和重新绑定都不会抹除历史角色。
管理员界面说明关闭策略不会恢复账号在该分组的普通用途。

普通调度、sticky／previous-response、型号目录和实际发送均排除这些账号；发送前的数据库
复核防止旧缓存绕回普通美元计费。未设置备用角色的独立分组／账号保持原行为，同一账号在
其他分组的原用途不受这一角色影响。统一编程原有订阅调度语义保留。
