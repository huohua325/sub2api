## 事故与账单口径

初始固定快照中，用户 3 的 API 实验月钱包已结算 150.45967 元，另有 12,909 条请求
保留为待对账，金额尚未计入。当时已有 2,936 条请求可凭最近日志证实少结算 73.54917 元。
随后通过供应商正规历史接口保全 37,804 条消费，合计 509.497010 元，与其账户
`used_quota / 500000` 精确相等。完整补账金额与各用户结果以本轮最终核对记录为准。

GlobalAI 本轮公开配置为 `quota_per_unit=500000`、汇率字段为 1。费用以消费记录的整数
quota 除以 500000 取得人民币，不用本地模型价卡、充值金额或猜测汇率追溯改价。
token 的 `unlimited_quota=true` 时，负的 `total_available` 不能解释成供应商账户透支。

供应商同一条记录可能同时包含两层 ID：

- `request_id`：GlobalAI 接收本站调用的请求，与本站保存的 `X-Oneapi-Request-Id` 对应。
- `upstream_request_id`：GlobalAI 再向其供应商发送的请求，不用于匹配本站调用。

原始记录保留两字段时必须优先取 `request_id`。不得按时间、价格或模型相近猜测请求归属。
规范化账单应保留原文件摘要、token 身份证据及 ID 来源；重复、冲突、无法确定归属的记录
单独保留。所有 Key 共享供应商余额，但各自消费仍须按本站真实请求归属用户及原周期。

## 历史更正

复用 `tools/globalai_reconcile.py` 保全账单并生成不可变补账计划。模型 Key 的日志接口仅返回
最近记录，历史使用供应商登录页面对应的 `/api/log/self` 只读分页接口。登录凭证只在本机
内存中使用，不进入命令参数、日志、Git 或服务器；导出数据与核对证据保存在忽略的 output。

实际应用的 `reconcile-experiment` 运维命令默认只读。写入要求固定程序源码 SHA、已验证
数据库备份摘要、完整原始证据和精确匹配计划；每一条都再次核对用户、Key、账号、原请求
起点及供应商请求 ID。已结算同额可重跑，异额冲突必须停止，不能覆盖旧结算。

补账和钱包、Key、订阅、账号计数在同一事务内完成。`experiment_quota_settlement_events`
追加保存原状态、原金额投影、实际费用及证据来源／摘要；原请求的 token、模型、身份和时间
不变。原零价是待结算投影，更新为已确认费用时仍在审计事件中完整保留旧值。

延迟入账归属原请求周期。旧月份请求不扣新月份额度；个人重置不改原始消费，也不能替代
供应商结算。不得为对齐余额而伪造请求、清空钱包或恢复旧数据库。

## 新增请求保护

### 异步并发试用（2026-11-18 后续授权）

平台所有者明确要求分离正在执行与已完成待账单请求，允许十路实验并发。本规则对显式
邀请的用户替代首版的一条未定价请求限制；未邀请用户仍沿用首版严格策略。

`settings.experiment_async_admission_policy` 保存版本 1 的 `user_ids`、`max_active`、
`max_outstanding` 和 `max_pending_age_seconds`，缺失时不开放。建议初次试用为 10 路执行、
100 条总未结算请求、最早账单等待 900 秒。名单与策略不写入迁移，升级与重启不能自动开放。
独立 settings 字段不改变原个人额度／周期；发布快照必须核对它没有被升级覆盖。

同用户跨 Key 在钱包行锁内准入；执行中占用和等待账单的记录去重统计。正常计费交接或
HTTP 处理结束后释放执行名额，已发送记录和费用责任保留。没有账单的完成请求保持 unknown，
正常 detached 计费可稍后完成交接；缺少结算身份或发送后崩溃的异常不能自动免费或重放。
只有从未发送的 reserved 可以按原规则恢复。

数量上限计算执行中加等待账单的全部未结算请求，跨月也不丢弃。账单延迟未越界时允许新请求；
达到数量／等待时间阈值时暂停新增、继续后台对账；队列恢复后自动恢复准入。已结算额度
耗尽仍拒绝新请求，已发送请求继续完整结算。该策略仅限制请求数量和等待时间，**不是可信的
人民币费用上界**，因此允许已在途费用造成额度超出；不得截断实际费用或宣称绝不超额。

页面分别显示已结算金额、正在运行数量和待核实数量。只有实际触发账单保护时显示暂停；
不能把未知费用显示为免费，也不能把后台对账显示为额度耗尽。

迁移 273 仅新增完成时间与普通索引，移除首版单用户唯一索引；原尝试、账单、结算审计及钱包
全部保留。已有并发尝试后不回退到会重新建立单用户唯一索引的旧启动程序，使用兼容程序修复。

### 首版严格策略（未邀请用户保留）

首版采用严格对账保护。在没有经过验证的单次费用上界时，每个用户跨 Key 只允许一个
未定价实验请求。当前周期仍有待核实费用时，暂停新增 GlobalAI 实验请求。该规则会降低
实验并行度，不能宣称与原并发 500 的体验相同；未来提高并行度需先验证可信成本上界。

真实发送前先持久化准入及发送检查点，发送后的超时、断流或缺少 usage 都保留未知占用，
不自动认为免费，不换账号或供应商重放，也不跟随重定向重复 POST。费用核实前不得自动解锁。
仅超过五分钟、仍未经过发送检查点的 reserved 请求可安全恢复；它与发送检查点原子竞争。

已发送但没有正常收费记录的请求仍须人工按证据核实。充值、重启、跨月和 TTL 都不是零费用
证据；本轮不提供根据当前配置猜补旧副作用的自动恢复。Simple Mode 原有不执行个人钱包
计费的语义保留，严格保护用于标准计费模式的 GlobalAI 实验。

首版覆盖普通 HTTP 生成及明确接入正式计费的同步路径。未覆盖的 WebSocket、Live、batch、
异步生成及独立计费创建按实际所选 GlobalAI 实验账号明确拒绝；其它供应商和编程用途不变。
免费 token 计数、模型发现等读取不创建无法结算的付费占用。

账单查询按供应商出口共享限速和短期缓存，一次页面可匹配多条待结算请求，429 尊重退避。
实验恢复器独立于 Codex/Grok 观察循环，按账号公平读取，旧记录不会阻止近期记录被核实。
Codex/Grok 原 shadow 模式保持不变，API 编程备用策略仍保持关闭。
