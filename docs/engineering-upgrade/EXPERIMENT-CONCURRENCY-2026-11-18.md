# 实验执行并发与后台账单

## 行为与操作

GlobalAI 实验不再因一条正常迟到账单占用全部执行容量。正在执行与已完成待结算分别计数，
账单继续按 `X-Oneapi-Request-Id` 与供应商 `request_id` 精确匹配；未知费用不是免费。
已发送请求不因超时自动释放费用责任或换供应商重放。

管理员在 **用户管理 → 编辑 → API 实验并发** 显式开启指定用户、填写 1–1000 的整数并点击
该区域的“保存”。它与用户资料的“更新”分别保存。每人可分配不同值，立即读取持久设置，
无需重启、换 Key 或修改客户端。降低上限不取消已运行请求，撤销只恢复旧的严格准入。
原用户总并发与账号容量仍共同生效，配置上限不等于服务器容量保证。

新用户及未邀请用户保持严格模式；升级不自动邀请所有人。初次运维授权仅包括管理员及本轮
明确指定的测试用户，十路只是初始值。后续管理员可逐人修改或撤销。

独立队列保护保留：个人配置的未结算数量上限为全局值与执行上限十倍中的较大值，最早账单
等待超过 900 秒时暂停新增，后台仍继续核实。已结算额度耗尽时拒绝新请求，在途费用照实入账。
该规则限制数量与时间，不构成人民币成本上界，可能因已在途费用超过个人额度。

## 实现与兼容性

- 应用：`11a1df54deff041bc68e6187c58ac0c54e3caa87`；基础分离实现为 `b9456681e`。
- 固定线上基线：`2898b7e4b478e581c1ccc34b65a898e98a1ed086`，SHA256
  `d82cda44b69b1f32adf4f3da33a62c9de4d03962185007e87c009a16e27af2ef`。
- 只新增迁移 273：完成时间、普通索引及移除首版单用户唯一索引；不改旧迁移和业务记录。
- `settings.experiment_async_admission_policy` 保留邀请名单及个人 `user_limits`，每次准入跨 Key
  在钱包行锁内计数；配置写入使用独立事务锁，保留其他人的分配。
- GET/PUT `/api/v1/admin/users/:id/experiment-concurrency` 分别使用独立读写权限。
- 程序失败仅允许回退固定的计费兼容基线，保留当前数据库、273 及策略，暂时恢复严格准入；
  已登记的 272 不会重建唯一索引。Codex/Grok shadow、钱包起点和全部计费审计继续保留。
